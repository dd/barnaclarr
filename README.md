# Barnaclarr

Hardlink-only импорт дополнительных аудиодорожек, субтитров и шрифтов после импорта видео Sonarr (сериалы) или Radarr (фильмы). Python, SQLite, fontTools, отдельный Docker-контейнер. Видео импортирует и переименовывает только Sonarr/Radarr.

Приложение рассчитано на TrueNAS SCALE 25.10. Проверено с Sonarr **5.0.0.2701** и Jellyfin **12.2**. Используется REST API `/api/v3`, совместимый также с Sonarr v4.

## Behavior

1. Sonarr (`/webhook/sonarr`) или Radarr (`/webhook/radarr`) присылает `Download` или `Rename` на защищённый Webhook. `Test` проверяет доступность без изменений. Остальные события игнорируются.
2. Событие сохраняется в SQLite до ответа HTTP 202. Один worker обрабатывает очередь; ошибки повторяются с задержкой, после шести попыток остаются в `failed`.
3. REST API даёт **текущие** пути видео и связь episode ID -> episode file ID. Устаревшие события для уже заменённого file ID игнорируются.
4. Приложение один раз рекурсивно сканирует релиз, определённый первым дочерним каталогом настроенного download root (например, `/mnt/media/downloads/anime/Release/...` ограничивает поиск `Release`), и использует результат для всех эпизодов события.
5. Sidecar связывается с исходным видео по одному из признаков, по порядку: явный mapping; полный stem видео (`Video.ass`, `Video.AniStar.mka`, `Video.signs.ass`); номер в изменяющейся части имён соседних файлов (`ReLIFE 01` ↔ `ReLIFE 01`, при любой схеме имён); `SxxExx` или абсолютный номер из Sonarr. Для фильма, если в раздаче одно обычное видео, все дорожки относятся к нему. Неоднозначность приводит к пропуску и записи причины.
6. Если Sonarr прислал только папку (On Import Complete), исходный файл берётся из истории импорта Sonarr (`droppedPath`), а при её отсутствии — из нумерации видео.
7. Папки бонусов (`Extras`, `Special`, `SPs`, `Omake`, `BD menu`, `Scan`, `BDCG`, `NCOP/NCED`, `OST`...) не участвуют в сопоставлении обычных эпизодов: одинаково названные видео в `Special/` не создают неоднозначности. Если сам эпизод импортирован из такой папки, используется именно она.
8. Имя назначения: `<stem видео Sonarr>.<название>.<язык>.<forced/sdh>.<ext>`. Название собирается из структуры раздачи без служебных слов: `ENG Subs/Crunchyroll ENG` → `Crunchyroll` (язык `en`), `Sounds/AniLibria [rus]` → `AniLibria` (язык `ru`), `Subs/GJM/Signs & Songs` → `GJM Signs`, `Russian Subtitles [Reanimedia]/Full [ass]` → `Reanimedia`. Хеши в имени не используются; при совпадении имён добавляется номер (`Track 2`). `idx/sub` получают одинаковое имя.
9. При повторе не создаются дубликаты. При Rename используются сохранённые hardlinks, даже если торрент уже удалён. При обновлении релиза новая версия дорожки заменяет ранее созданную приложением и неизменённую ссылку с тем же именем; остальные старые ссылки удаляются. Изменённые вручную файлы не трогаются: такой конфликт останавливает обработку. При неполном сопоставлении старые дорожки сохраняются для ручной проверки.

Поддерживаются аудио `mka/aac/ac3/eac3/flac/opus/ogg/mp3/m4a/dts/wav`, субтитры `ass/ssa/srt/sub/idx/vtt/sup/smi`, шрифты `ttf/otf/ttc/otc`. Шрифты в архивах (`Fonts.7z`, `.zip`) не распаковываются. Поддержка воспроизведения конкретного формата зависит от Jellyfin и клиента.


## Fonts

fontTools читает внутренние family/subfamily, включая все лица TTC. Файлы размещаются hardlinks в `fonts/` рядом с видео и в `/mnt/media/.barnaclarr-fonts`. Имя включает family, style и хеш содержимого; исходные байты не меняются.

Разбор шрифтов кэшируется в SQLite по inode, поэтому сезонный пакет не разбирает одни и те же файлы для каждой серии. Повреждённый шрифт, в том числе в общей библиотеке, только попадает в журнал и не останавливает импорт. Идентичные шрифты дедуплицируются. Разные шрифты с одинаковой family/style сохраняются локально, но конфликтующий вариант не добавляется в общую библиотеку. Это не гарантирует правильный выбор шрифта всеми клиентами: отдельные релизы могут требовать несовместимые версии одной family. Такие случаи отражаются в журнале и требуют выбора администратором.

Общая библиотека автоматически не очищается: шрифты могут использоваться несколькими сериалами. При Rename шрифты, учтённые за эпизодом, получают ссылки в новой папке; прежняя папка fonts сохраняется, поскольку может использоваться другими видео. Не выполняется извлечение вложений MKV, встраивание шрифтов или конвертация WOFF2.


## Safety contract

- Единственная операция переноса содержимого: `os.link`. Нет копирования, перекодирования, изменения torrent-файлов, chmod/chown исходников.
- Download и library roots ограничены конфигурацией; symlinks и `..` запрещены. При создании ссылок каждый родитель открывается с `O_NOFOLLOW`.
- Проверяются inode/device/size/mtime. Сохраняется журнал намерения до создания ссылки, что позволяет восстановиться после прерывания.
- Чужие файлы не перезаписываются и не присваиваются приложению. Конфликт останавливает обработку, а уже созданные ссылки безопасно распознаются при повторе.
- SQLite и lock-файл лежат в постоянном `/state`; не запускать несколько экземпляров с разными базами для одной медиатеки. Не удалять базу между обновлениями.
- `BARNACLARR_DRY_RUN=true` по умолчанию: медиа и links-журнал не изменяются. Служебная очередь/SQLite и журналы могут записываться. CLI `event` дополнительно требует `--apply` для записи при `dry_run=false`.
- HTTP token обязателен, минимум 32 символа. API key и token задаются переменными окружения или файлами (`*_FILE`) и не попадают в логи. Sonarr API используется только для GET (`series`, `episode`, `episodefile`, `history/series`).
- Контейнер работает UID:GID 568:568, без capabilities, без Docker socket, с read-only root filesystem. Общий media mount должен быть RW для hardlinks. Он предоставляет технический доступ и к загрузкам; приложение ограничивает действия программно. Два отдельных RO/RW mounts нарушают hardlinks, см. [storage.md](docs/storage.md).

Не следует редактировать содержимое созданных hardlinks вручную: это тот же inode, что у раздаваемого файла. Приложение само содержимое не записывает. Конкурентное злонамеренное изменение доверенными локальными процессами в последний момент между проверкой и удалением не является поддерживаемой моделью доступа; сервисы медиатеки должны быть доверенными.


## Matching configuration

`BARNACLARR_DOWNLOAD_ROOTS` (`download_roots`) должны указывать на отдельные категории загрузок, не `/mnt/media` и не папку конкретного релиза. У loose files без отдельной папки релиза нет безопасной границы поиска: они отклоняются. Сборник из нескольких сериалов с повторяющимися номерами требует явных mappings.

Язык определяется по папкам (`ENG`, `English`, `[eng]`, `RUS`, `German`, двух- и трёхбуквенные коды ISO, названия языков на английском и русском); более глубокая папка важнее. Из имени файла учитываются только явные метки: `[ENG]`, `.eng.ass`, а при точном совпадении stem — всё после stem видео. Если язык не найден, используется `BARNACLARR_DEFAULT_LANGUAGE` (по умолчанию `und`). Группа — подпись в имени файла после имени видео, а если её нет, оставшиеся слова самой глубокой папки с названием (названия из разных мест не склеиваются), после удаления языка и служебных слов (`Sound`, `Audio`, `Dub`, `Subs`, `Озвучка`, `Full`, `ass`, `5.1`, `DTS`...). Более поздние `rules` из `config.toml` переопределяют язык и группу.

`forced` и `sdh` сохраняются как флаги. `Signs`/`Inscriptions`/`Надписи` добавляют к названию `Signs`, а не флаг: это не универсальный признак принудительного показа, и он не превращается автоматически в `forced`. Название стоит перед языком, поэтому Jellyfin корректно распознаёт язык.

```toml
[[rules]]
pattern = '(?i)funi(mation)?'
language = "en"
group = "Funimation"

[mappings]
"Release/Subs/Show - 13 OVA.ass" = [1234]
```

В mappings используются **Sonarr episode IDs**, не абсолютные номера и не episodeFile IDs. Полный ключ отсчитывается от download root. `S00E01` поддерживается непосредственно. `13 OVA`, диапазоны и multi-episode sidecars без точного stem требуют mapping. Для видео с несколькими эпизодами список должен совпадать со всеми episode IDs этого видео; приложение не режет аудио/субтитры по времени.


## Development

```sh
python3 -m venv .venv
.venv/bin/pip install -e '.[test]'
.venv/bin/pytest -q
.venv/bin/ruff check .
.venv/bin/ruff format --check .
git diff --check
docker build -t ghcr.io/dd/barnaclarr:dev .
```

Тесты не обращаются к сервисам: Sonarr заменён in-memory объектом, HTTP проверяется на буферах без сокетов, шрифты создаются тестовым FontBuilder, файловые операции выполняются во временных каталогах.


## Releases

Версия задаётся только в `pyproject.toml`. Релиз: поднять версию, закоммитить и поставить тег `vX.Y.Z`; GitHub Actions проверит тесты и совпадение тега с версией и опубликует образ `ghcr.io/dd/barnaclarr:X.Y.Z`.


## Roadmap

### До релиза 0.1.0

- [ ] Автоочистка старых выполненных задач в `jobs`.
- [ ] Предупреждение при запуске, если в `BARNACLARR_DOWNLOAD_ROOTS` указана общая папка загрузок вместо отдельных категорий.
- [ ] `BARNACLARR_PATH_MAPPINGS`: подмена путей, если контейнер подключён не так, как Sonarr или Radarr.

### После релиза

- [ ] Обработка медиатеки, импортированной до установки модуля, по истории импорта Sonarr и Radarr.
- [ ] Удаление созданных модулем дорожек и шрифтов, когда Sonarr или Radarr удаляет файл (On Episode File Delete, On Movie File Delete).
- [ ] Обновление библиотеки Jellyfin после создания дорожек, без ручного сканирования.
- [ ] Точная граница раздачи через qBittorrent по `downloadId` из события.
- [ ] Импорт бонусов (NCOP, NCED, промо) в подпапки `extras/` и т.п. рядом с сериалом или фильмом.
- [ ] Необязательный флаг `forced` для надписей.
- [ ] Приложение в каталоге TrueNAS (community) и документация на английском.
