# Storage requirements

Приложение переносит дорожки и шрифты только через hardlinks (`link(2)`), без копирования. Hardlink возможен только внутри одной файловой системы, поэтому к хранилищу есть жёсткие требования.


## One dataset, one mount

- Загрузки торрент-клиента, медиатека Sonarr и общая папка шрифтов (`font_root`) должны лежать **в одном ZFS dataset**. Папка шрифтов — обычный каталог внутри него, не отдельный dataset.
- В контейнер этот dataset подключается **одним bind mount**, например `MEDIA_PATH:/mnt/media`. Два отдельных mount'а одного и того же dataset (загрузки и медиатека по отдельности) Docker представляет как разные файловые системы, и `link(2)` возвращает `EXDEV`.
- Пути в `config.toml` указываются так, как их видит контейнер: `/mnt/media/...`.
- Sonarr и торрент-клиент должны видеть файлы по тем же путям, что и это приложение: `sourcePath` из вебхука Sonarr используется как есть. Если пути различаются, выровняйте mount'ы контейнеров или remote path mappings Sonarr.

Одинаковый `st_dev` у двух путей не гарантирует успех: решающей проверкой остаётся сам `link(2)`. Приложение при `EXDEV` никогда не переходит на копирование, задача завершается ошибкой.

Ожидаемые результаты на типичной установке TrueNAS:

| Scenario | Result |
| --- | --- |
| Два каталога под одним bind mount одного dataset | Успех: одинаковые device/inode, `st_nlink=2` |
| Те же каталоги как два отдельных bind mounts | `EXDEV` / Cross-device link |
| Источник и назначение в разных datasets | `EXDEV` / Cross-device link |


## Checking your NAS

[`scripts/nas-hardlink-probe.py`](../scripts/nas-hardlink-probe.py) проверяет эти сценарии на вашем хранилище. Он создаёт только временные каталоги `.anime-sidecar-probe-*` и удаляет их после проверки, запускает одноразовый контейнер из уже существующего образа (по умолчанию Sonarr) с `--network=none`, без capabilities, и ничего не скачивает.

```sh
sudo python3 scripts/nas-hardlink-probe.py --media /mnt/<pool>/<media-dataset> --other /mnt/<pool>/<other-dataset>
```

`--container` задаёт имя контейнера, чей образ используется (по умолчанию `ix-sonarr-sonarr-1`).


## Permissions

- Контейнер работает от UID:GID 568:568, как приложения TrueNAS. Ему нужны чтение каталогов загрузок и запись в каталоги сериалов и `font_root`.
- Не применяйте рекурсивный `chmod`/`chown` к медиатеке. Если смена владельца в media ограничена ACL, создавайте новые каталоги сразу от UID 568.
- `EACCES` при работе означает права/ACL, `EXDEV` — неверные datasets или mount'ы. Исправляется конфигурацией хранилища, не правами root для контейнера.


## Sonarr settings that matter

- Sonarr сам должен импортировать видео hardlink'ами (Settings > Media Management > Use Hardlinks instead of Copy), иначе раздача и медиатека не будут связаны.
- Settings > Media Management > Import Extra Files: если включено, Sonarr тоже копирует субтитры рядом с видео. Чтобы дополнительными файлами управляло только это приложение, отключите эту настройку. Она глобальная и затрагивает все сериалы, поэтому решение остаётся за администратором; приложение не удаляет файлы, созданные не им.
